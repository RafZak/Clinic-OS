# Spec — Quizzes interactifs (J10 polish)

> Direction validée : **D3 Hybride** (parsing déterministe + IA en couche d'aide optionnelle).
> Mode validation : **B** (≥ 80% = quiz validé, score visible Karpathy + dashboard).

## Objectif

Transformer les 4 quiz Drive (DOCX/PDF) en expérience interactive in-app, avec score persisté, badge de validation, et boucle vers la mémoire organisationnelle.

## Périmètre

- 4 fichiers source (déjà ingérés en `knowledge_chunks`) :
  - `Quizz SBL-REFERENCE.pdf` (programme `reference`)
  - `Quiz Personnel Acceuil.docx` (programme `personnel-accueil`)
  - `Quizz convaincre au telephone.docx` (programme `convaincre-telephone`)
  - `Quizz SBL - Audio Vente.docx` (programme `audio-vente`)
- Chaque fichier contient **N quiz** ancrés à un module (`Quiz #N (apres la video #M)`).
- Types de question gérés : MCQ simple, MCQ multi-choix, Vrai/Faux. La question d'ordonnancement (1 cas) est convertie en MCQ multi-choix au parsing.

## Architecture

### 1. Parsing (eager, one-shot)

- Script `scripts/parse-quiz.ts` (`pnpm parse:quiz`) :
  - Charge tous les chunks `WHERE source_file ILIKE '%quiz%'` groupés par fichier
  - Une passe Sonnet 4.6 par fichier, `tool_use` `submit_quiz_set` (schéma strict)
  - Upsert dans tables DB
- Idempotent : `ON CONFLICT (program_slug, ordinal) DO UPDATE`.

### 2. Schéma DB (3 tables)

```sql
CREATE TABLE quiz_sets (
  id          uuid PRIMARY KEY,
  program_slug text NOT NULL,
  module_number int,            -- module ciblé (NULL si quiz global)
  ordinal     int NOT NULL,     -- Quiz #1, #2, #3 dans le programme
  title       text NOT NULL,
  pass_threshold int DEFAULT 80,
  source_file text NOT NULL,
  created_at  timestamptz DEFAULT now(),
  UNIQUE (program_slug, ordinal)
);

CREATE TABLE quiz_questions (
  id          uuid PRIMARY KEY,
  quiz_set_id uuid REFERENCES quiz_sets(id) ON DELETE CASCADE,
  position    int NOT NULL,
  prompt      text NOT NULL,
  kind        text NOT NULL,    -- 'single' | 'multi' | 'boolean'
  choices     jsonb NOT NULL,   -- [{ id: 'a', label: '...' }, ...]
  correct_ids text[] NOT NULL,  -- ['a'] for single/boolean, ['a','b','d'] for multi
  explanation text NOT NULL,
  related_module int,           -- pour deep-link nudge si raté
  UNIQUE (quiz_set_id, position)
);

CREATE TABLE quiz_attempts (
  id            uuid PRIMARY KEY,
  quiz_set_id   uuid REFERENCES quiz_sets(id) ON DELETE CASCADE,
  practitioner_id uuid REFERENCES practitioners(id) ON DELETE CASCADE,
  score         int NOT NULL,    -- 0-100
  passed        boolean NOT NULL,
  answers       jsonb NOT NULL,  -- { question_id: ['a','c'], ... }
  duration_ms   int,
  completed_at  timestamptz DEFAULT now()
);

CREATE INDEX quiz_attempts_practitioner_idx ON quiz_attempts(practitioner_id);
CREATE INDEX quiz_sets_program_idx ON quiz_sets(program_slug, ordinal);
```

### 3. Identité utilisateur (pas d'auth)

- Helper `lib/quiz-identity.ts` : `getCurrentPractitioner(role)`
  - `audioprothesiste` → Claire Moreau (deja en DB)
  - `assistant` → Sophie Bernard (déjà en DB depuis J9)

### 4. UI

- **Dans l'accordéon module** (`components/catalogue/program-modules.tsx`) :
  - Si un `quiz_set` cible ce module : carte "Quiz du module N" + état (non commencé / en cours / validé ✓ / à repasser ✗) + bouton "Lancer le quiz" / "Repasser".
  - Quiz global (sans module) → carte tout en bas du programme dans une section "Quiz transverses".
- **Modal/drawer plein écran** pour passer le quiz :
  - 1 question par écran, navigation Précédent/Suivant
  - Choix visuels (radio MCQ simple/Vrai-Faux ; checkbox MCQ multi)
  - Validation à la fin → page résultats : score % + barre + liste des questions avec bonne/mauvaise réponse + explication
  - Sur chaque mauvaise réponse, **bouton discret "Comprendre cette question"** → fetch Haiku pour explication + citation Layer A (réutilise `lib/retrieval/synthesize.ts`)
  - Si raté : nudge en bas "Vos lacunes pointent vers le module N" → deep-link vers `/catalogue/<slug>#module-N` (via `lib/learning-links.ts`)

### 5. Server actions

- `submitQuizAttempt(quizSetId, answers, durationMs)` :
  - Calcule le score (% de questions correctes)
  - Insère dans `quiz_attempts` (avec `practitioner_id` du rôle courant)
  - Si `passed` → append direct dans la fiche Karpathy `practitioners/<slug>.md`, section "## Formation" (créée si absente). Format : `- ✓ Quiz {title} validé le {date} ({score}%)`. Pas de full Sonnet rewrite, juste un append-section via `lib/vault/storage.ts`.
  - Retourne `{ score, passed, attemptId }`
- `getQuizExplanation(questionId)` (route API streaming Haiku) : explication 2 phrases + 1 citation Layer A.

### 6. Couches optionnelles (J10 si temps)

- **Dashboard** : compteur "X quiz validés cette semaine" dans la section actuelle, ou nudge "Quiz du module 7 à passer" basé sur `weak-step` détecté.
- **Sidebar badge** Catalogue : pastille brand si quiz validé aujourd'hui.

## Points de vigilance

- **Parsing PDF de Référence** : si le PDF est mal extrait (fréquent), le parser Sonnet doit pouvoir échouer proprement (log + skip ce fichier). Audio Vente / Convaincre / Personnel sont DOCX → safe.
- **Coût parsing** : 4 fichiers × Sonnet 4.6 ≈ ~$0.30 total, one-shot.
- **Karpathy append** : pas de IA dans la boucle pour rester rapide et déterministe. Format simple, lisible dans Obsidian.
- **Scoring multi-choix** : binaire (toutes les bonnes réponses cochées + aucune mauvaise = correct, sinon faux). Pas de partial credit pour rester simple.
